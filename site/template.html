Wave 1 / Prototype

Choose small, testable actions.

  • GitHub, Asana, Airtable: read one issue, task or record, then exercise scoped write permissions.
  • Stripe, Plaid, Salesforce: use test data and developer environments; production access is a later milestone.
  • Mermaid CLI: wrap local rendering with input, timeout and output-file limits.
Wave 2 / Resolve the account path

Ask a narrow entitlement question.

  • Mailchimp, Notion, Reducto: confirm the exact free/trial API allowance before promoting the verdict.
  • iPayX: a free MCP path is documented, but REST pages disagree on base URL and request schema.
  • DealCloud, Front, Pylon: secure an authorized admin and a tenant with the required permissions.
Wave 3 / Outreach & identity

Resolve the gate before engineering.

  • LinkedIn Ads, Amazon SP-API: prepare the app approval and partner-access path.
  • PitchBook: obtain the licensed API contract, auth details and commercial terms.
  • Paygent Connect: request the exact vendor URL. The name alone cannot support an auth verdict.

Priority is a feasibility recommendation, not a claim about customer demand. Before committing engineering capacity, combine this queue with requested workflows, expected usage and integration maintenance cost.

What actually ran

The initial collector fetched /100 seed URLs successfully in seconds. That timing is only the HTTP pass, not the whole research process.

The final source ledger covers unique cited URLs: returned HTTP 200; failed or were blocked. A 200 response can still be an empty JavaScript shell.

The script is a discovery baseline, not an autonomous fact verifier. Semantic review was performed by the Codex agent in this session. No Composio SDK integration is claimed.

Errors that changed the outcome

“Enterprise” caused a false gate.

Freshdesk’s trial API limit is explicitly documented. A keyword elsewhere on the page made the baseline call it gated. Review promoted the scoped trial path.

Navigation polluted the protocol.

Mailchimp and MongoDB Atlas were labeled GraphQL by keyword hits. Their scoped Marketing and Admin APIs are REST. Product identity and page section matter.

Browser recovery changed the evidence.

Gumroad’s shell hid its OAuth/REST docs. Consensus’s old MCP URL returned 404; the current docs exposed a shared free API/MCP allowance. iPayX required following a separate MCP guide to establish its free path.

05 / Limits & human review

The final check belongs to a person.

Boundaries of this work

Public documentation was reviewed. No paid accounts were purchased, credentials generated, authenticated API calls made, or customer data accessed for the assessment.

Vendor documentation can be incomplete or stale. MCP evidence is a lower bound from checked sources, not an exhaustive registry. An unknown plan entitlement stays unknown. Paygent Connect’s identity and PitchBook’s exact contract remain open.

Next validation: obtain authorized test access for the chosen prototype, execute one read and one reversible write, test pagination and rate limits, and document the response. Then have a person independently check the facts.
